# AudioCanvas: материал для презентации

Тема 8: доступный HCI-интерфейс, где дети с нарушением зрения учатся создавать визуальные
материалы с помощью ИИ и понимать, что на них изображено, по аудиоописанию.

## 1. Что это за сайт (1–2 слайда)

**AudioCanvas** — веб-сайт для детей 7–14 лет с нарушением зрения (слабовидящих и незрячих).
Ребёнок говорит или пишет, что хочет увидеть («создать картинку: кот на крыше»), ИИ рисует картинку,
а сайт сразу озвучивает её описание: коротко и подробно («слева красный круг, справа синий квадрат»).
В уроках ребёнок учится сам описывать картинки словами.

**Для кого.** Основной пользователь — ребёнок со screen reader или только с клавиатурой и голосом.
Вторичный — учитель или родитель, который просматривает работы и может исправить описание.

**Что умеет**
- Создание картинки по голосовому или текстовому запросу, на казахском и русском.
- Описание в двух уровнях: одно предложение и подробное (объекты, цвета, расположение).
- Аудио-подсказка помощника при открытии сайта: через 3 секунды сама рассказывает, как управлять; `Enter` её останавливает.
- 6 коротких уроков («Что такое описание», «Слева и справа», «Цвета и формы», «Сверху, снизу, в центре», «С чего начать», «Опиши свою работу») с обратной связью без наказаний.
- Галерея «Мои работы»: поиск, прослушивание, редактирование описания, удаление.
- Экспорт: ZIP с картинкой, текстом описания и аудиофайлом (MP3).
- Настройки доступности: высокий контраст, шрифт 100–200%, скорость речи, отключение анимаций и горячих клавиш.

**Сценарий (демо на защите)**
1. Открыть сайт: звучит приветствие помощника, `Enter` — пропустить.
2. Сказать или ввести «создать картинку: кот на крыше».
3. Слышно «Картинка создаётся», затем «Готово» и краткое описание.
4. «Слушать» — подробное описание. «Сохранить» — работа в галерее.
5. Открыть работу, скачать ZIP с аудио.

## 2. Принципы HCI (почему так сделано)

| Принцип | Как реализован |
|---|---|
| Аудио как основной канал | Каждое действие озвучивается: статусы, переходы, подсказки, ошибки |
| Работа без мыши | Полная клавиатурная навигация, голосовые команды, текстовая команда как равноправная замена голосу |
| Предсказуемая простая навигация | 4 раздела, единый порядок фокуса, ссылка «Перейти к содержимому», фокус на заголовке при смене страницы |
| Минимум когнитивной нагрузки | Короткие фразы, один шаг на экран в уроках, подсказки вместо штрафов за ошибки |
| Прозрачность ИИ | Везде пометка «создано ИИ, может содержать ошибки»; учитель или ребёнок может исправить текст, тогда пометка меняется на «отредактировано человеком» |

## 3. Архитектура (1–2 слайда)

```
 Браузер (React + TypeScript)                    Сервер (FastAPI, Python)
┌──────────────────────────────┐   /api    ┌────────────────────────────────┐
│ Интерфейс, уроки, галерея    │ ───────▶ │ Роутеры: generate, describe,     │
│ Озвучка и голос (Web Speech) │          │          materials, progress     │
│ Вступление (готовое аудио)   │ ◀─────── │ Модерация · кэш · лимиты         │
│ Доступность: фокус, live,    │          │ Адаптеры ИИ (providers/)         │
│ горячие клавиши, настройки   │          └──────┬───────────────┬───────────┘
└──────────────────────────────┘                 │               │
                                      ┌──────────▼───┐    ┌──────▼──────────────┐
                                      │ SQLite (файл)│    │ Внешние ИИ-сервисы  │
                                      │ работы,      │    │ Cloudflare Workers  │
                                      │ описания,    │    │ AI (картинки)       │
                                      │ прогресс     │    │ Google Gemini       │
                                      └──────────────┘    │ (описание, перевод, │
                                                          │  озвучка)           │
                                                          └─────────────────────┘
```

**Ключевая идея: адаптеры.** Все внешние сервисы закрыты интерфейсами
(`ImageProvider`, `DescriptionProvider`, `TTSProvider`, а во фронтенде `TTSProvider` и
`STTProvider`). Роутеры знают только интерфейс, поэтому провайдера можно заменить настройкой в
`.env`, без переписывания кода. Это защищает проект от смены лимитов и цен. Для разработки есть
провайдеры-заглушки, которые работают без ключей и интернета.

**Как проходит запрос «создать картинку»**
1. Фронтенд отправляет `POST /api/generate` с запросом и языком.
2. Сервер проверяет запрос: длина, опасные слова (kk/ru/en), персональные данные (почта, телефон, ссылки).
3. Если такой запрос уже был, картинка берётся из кэша и лимит не тратится.
4. Запрос переводится на английский (Gemini), потому что модель рисует точнее по-английски, и проверяется ещё раз.
5. Картинку рисует FLUX.1 schnell в Cloudflare Workers AI.
6. `POST /api/describe`: Gemini смотрит на картинку и **за один проход** пишет описание на обоих языках, поэтому казахский и русский вариант всегда говорят об одном и том же.
7. Ответ модели проверяется модерацией, и только потом озвучивается ребёнку.
8. Фронтенд озвучивает «Готово» и краткое описание.

## 4. Технологии

| Слой | Что использовали |
|---|---|
| Фронтенд | React 19, TypeScript, Vite, React Router |
| Бэкенд | Python, FastAPI, Pydantic |
| База данных | SQLite (локальный файл, без отдельного сервера) |
| Голосовой ввод | Web Speech API браузера (распознавание речи) |
| Озвучка в интерфейсе | Web Speech `speechSynthesis` браузера |
| Озвучка для экспорта и вступления | Gemini TTS (казахский и русский), конвертация в MP3 через ffmpeg |
| Генерация картинок | Cloudflare Workers AI, модель FLUX.1 schnell |
| Описание, перевод запроса | Google Gemini (`gemini-3.1-flash-lite`) |
| Дизайн | Google Stitch: дизайн-система «Luminous Haptic Canvas»; шрифты Atkinson Hyperlegible Next и Noto Sans |
| Проверка доступности | axe-core, ESLint `jsx-a11y`, Lighthouse, Chrome, ручные проверки со screen reader |
| Тесты и CI | Vitest, pytest, ruff, GitHub Actions (файл `ci.yml`) |

## 5. API и стоимость (1 слайд)

Все ключи хранятся только на сервере в `.env`, на фронтенд они не попадают.

| Сервис | Для чего | Бесплатно? |
|---|---|---|
| Web Speech API (браузер) | Распознавание речи и озвучка интерфейса | **Да**, без ключа. Зависит от браузера (лучше всего Chrome); казахский голос может отсутствовать |
| Cloudflare Workers AI (FLUX.1 schnell) | Генерация картинок | **Да, в пределах 10 000 «нейронов» в сутки.** Одна картинка 1024×1024 стоит около 173 нейронов, то есть **примерно 57 картинок в день**. Выше лимита нужен платный план |
| Google Gemini (flash-lite) | Описание картинок, перевод запроса | **Да, есть бесплатный уровень** с ограничениями по запросам |
| Google Gemini TTS | Озвучка для экспорта аудио и записи вступления | Использован обычный ключ без привязки оплаты; условия бесплатного уровня для TTS отдельно не проверялись |
| Gemini Image (генерация картинок Google) | Не используется | **Нет**: у моделей генерации картинок Google нет бесплатного уровня. Поэтому выбран Cloudflare |
| Google AI Pro (подписка) | Не используется для API | Подписка не покрывает вызовы API, они оплачиваются отдельно |
| SQLite, шрифты, Chrome, Lighthouse | Хранение данных, оформление, проверки | **Да**, всё локально |

**Как экономим лимиты:** кэш одинаковых запросов, лимит запросов на клиента (10 картинок и
20 описаний в минуту), единое описание на два языка (один вызов вместо двух), вступление записано
заранее и не вызывает ИИ при каждом открытии.

**Итог:** вся связка работает бесплатно в пределах лимитов, достаточных для разработки, защиты и
тестов с группой детей. Для массового использования потребуется платный тариф или другой провайдер,
заменяемый через адаптеры.

## 6. Безопасность и этика

- Модерация запросов и ответов модели, запрет персональных данных, лимиты запросов.
- Не собираются лишние данные: никаких имён и почты, работы разделяются случайным идентификатором устройства.
- Описания помечены как созданные ИИ и редактируются человеком.
- Защита от SSRF: описание строится по `image_id`, сервер не ходит по ссылкам, присланным пользователем.
- SVG и изображения отдаются с запрещающей политикой безопасности контента.

## 7. Доступность и тестирование (1 слайд)

| Проверка | Результат |
|---|---|
| Lighthouse accessibility, 6 страниц | **100** на каждой (порог 95) |
| axe-core на всех страницах | 0 нарушений |
| Контраст палитры (обычная и высококонтрастная темы) | ≥ 4,5:1 для текста, ≥ 3:1 для рамок и фокуса |
| Масштаб шрифта 200% при ширине 320 px | нет горизонтальной прокрутки |
| Цели касания | не меньше 44 px |
| Автоматические тесты | 106 фронтенд и 70 бэкенд |

Найденные и исправленные дефекты: горизонтальная прокрутка при 200% на узком экране, сжатые
флажки, лишний контраст фокуса, несоответствие подписи и имени у кнопок A−/A+.

**Не выполнено:** проверка со screen reader (NVDA, VoiceOver, TalkBack) и юзабилити-тест с 3–5
пользователями с нарушением зрения. Подготовлены сценарии и протокол в `docs/`.

## 8. Ограничения (честно)

- Нет входа: работы разделяются идентификатором устройства. Нет режима учителя.
- Распознавание речи и казахский голос зависят от браузера; автозвук вступления может потребовать разрешения на звук.
- Описания ИИ могут быть неточными; картинка иногда содержит случайные «подписи».
- Качество казахских текстов уроков и озвучки проверено на глаз, нужна проверка носителем и педагогом.
- Бесплатный лимит картинок около 57 в день; данные хранятся локально в файле SQLite.
- Деплой не выполнялся: проект запускается локально.
