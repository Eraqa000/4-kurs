# План проекта: AudioCanvas — доступный веб-интерфейс для детей с нарушением зрения

Тема 8: разработка доступного HCI-интерфейса для обучения детей с нарушением зрения созданию аудио-сипаттамалы визуальных материалов с помощью ИИ.

## Инструкция для Claude Code

Реализуй проект по этапам ниже. Правила работы:
- Выполняй этапы строго по порядку. После каждого этапа запускай проверки и коротко отчитывайся (что сделано, что проверено, что осталось).
- Не переходи к следующему этапу, пока не выполнены критерии готовности текущего.
- Перед установкой тяжёлых зависимостей или изменением архитектуры спрашивай подтверждение.
- Все ключи API хранить только в `.env`, никогда не коммитить. Создай `.env.example`.
- Язык интерфейса: казахский (основной), русский (второй), переключаемый. Комментарии в коде и README: русский.

## 1. Цель и аудитория

**Цель:** сайт, где ребёнок с нарушением зрения (слабовидящий или незрячий) может создавать визуальные материалы (картинки, простые схемы, мини-презентации) с помощью ИИ. Каждый материал сопровождается аудиоописанием, и ребёнок учится понимать, что изображено.

**Пользователи:** дети 7-14 лет, использующие screen reader (NVDA, VoiceOver, TalkBack) или работающие только с клавиатурой и голосом. Вторичная роль: учитель или родитель, который просматривает работы.

**Принципы HCI (обоснование):**
- Аудио как основной канал обратной связи: каждое действие озвучивается.
- Полная работа без мыши: клавиатура и голос.
- Предсказуемая простая навигация: не более 3 уровней, единый порядок фокуса.
- Минимум когнитивной нагрузки: короткие фразы, один шаг на экран.

## 2. Стек и обоснование

| Слой | Выбор | Почему |
|---|---|---|
| Frontend | React + TypeScript + Vite | Знаком, быстрая разработка, хорошая поддержка a11y-инструментов |
| Backend | FastAPI (Python) | Знаком, удобно подключать ИИ-модели |
| БД и аутентификация | Supabase (PostgreSQL) | Уже используется в других проектах, есть бесплатный уровень |
| Голосовой ввод (STT) | Web Speech API (основной), запасной: Azure Speech F0 или Speechmatics | Бесплатно, без ключа, работает в браузере |
| Озвучка (TTS) | Web Speech `speechSynthesis` (по умолчанию), опционально Google Cloud TTS или ElevenLabs | Бесплатный базовый вариант плюс улучшаемое качество и казахский язык |
| Генерация изображений | Подключаемый провайдер (интерфейс `ImageProvider`) | Бесплатные лимиты меняются, провайдер должен заменяться без переписывания |
| Описание изображений | Vision-модель (интерфейс `DescriptionProvider`) | Генерирует alt-text и подробное аудиоописание |
| Тесты a11y | axe-core, Lighthouse, ручная проверка NVDA/VoiceOver | Автоматика ловит около 30-40% проблем, остальное нужно вручную |

**Важно:** все внешние ИИ-сервисы закрыть интерфейсами-адаптерами (`TTSProvider`, `STTProvider`, `ImageProvider`, `DescriptionProvider`) с фолбэком на браузерные API. Тогда проект не ломается при смене лимитов.

## 4. Этапы реализации

### Этап 0. Инициализация
- Создать монорепозиторий, настроить Vite+React+TS, FastAPI, линтеры (ESLint с `jsx-a11y`, Prettier, ruff).
- Подключить Supabase (таблицы ниже), настроить `.env.example`.
- **Готово, когда:** фронт и бэк запускаются локально, `npm run lint` и `pytest` проходят.

### Этап 1. Каркас доступности (делается ДО функционала)
- Семантическая разметка: `header`, `nav`, `main`, `footer`, правильные заголовки `h1-h3`.
- Ссылка «Перейти к содержимому» первой в порядке фокуса.
- Видимый фокус (контур не менее 3px, контраст не менее 3:1).
- Глобальная `aria-live` область для озвучки статусов («Картинка создаётся», «Готово»).
- Менеджер фокуса при смене страницы и модальных окон.
- Настройки: высокий контраст, размер шрифта (100-200%), скорость речи, отключение анимаций (`prefers-reduced-motion`).
- Горячие клавиши с возможностью отключения; список клавиш озвучивается по `?`.
- **Готово, когда:** вся навигация проходит клавиатурой, axe-core не находит критических нарушений.

### Этап 2. Аудио-слой
- Адаптеры `TTSProvider` и `STTProvider`. Реализации: Web Speech (по умолчанию) и один облачный провайдер (по выбору, за флагом).
- Озвучка всех подсказок интерфейса, повтор по клавише `R`, пауза и остановка по `Esc`.
- Голосовые команды: «создать», «слушать», «повторить», «назад», «сохранить».
- Фолбэк: если браузер не поддерживает STT, показать клавиатурный/текстовый ввод и озвучить это.
- **Готово, когда:** основной сценарий выполняется без мыши и без экрана, только голосом и клавиатурой.

### Этап 3. Генерация и описание материалов
- Бэкенд: `POST /generate` (промпт → изображение через `ImageProvider`), `POST /describe` (изображение → краткий alt-text и подробное описание через `DescriptionProvider`).
- Описание в двух уровнях: короткое (1 предложение) и подробное (композиция, цвета, объекты, расположение: «слева», «справа», «в центре»). Язык: kk или ru.
- Ограничения скорости и кэширование результатов (контролировать расход бесплатных лимитов).
- Модерация детского контента: фильтр промптов и результатов, запрет персональных данных.
- **Готово, когда:** по голосовому запросу создаётся картинка, и описание озвучивается автоматически.

### Этап 4. Обучающий режим
- 5-8 коротких уроков: «Что такое описание изображения», «Слева и справа», «Цвета и формы», «Опиши свою работу».
- Каждый урок: одна цель, озвученная инструкция, задание, аудио-обратная связь (поощрение без перегрузки).
- Прогресс хранится в Supabase.
- Режим учителя: просмотр работ ребёнка, редактирование описания.
- **Готово, когда:** ребёнок проходит урок от начала до конца без помощи зрения.

### Этап 5. Галерея и экспорт
- Список работ с озвучиванием заголовков, воспроизведение описания, редактирование.
- Экспорт материала: изображение + описание в тексте + MP3/аудиофайл описания.
- **Готово, когда:** работу можно сохранить, найти, прослушать и скачать.

### Этап 6. Тестирование и доступность
- Автоматика: axe-core в CI, Lighthouse accessibility не менее 95.
- Ручная проверка: NVDA + Firefox/Chrome, VoiceOver + Safari, TalkBack на Android.
- Чек-лист WCAG 2.1 AA (контраст 4.5:1, цели касания не менее 44px, не использовать только цвет для смысла, тайминги).
- Юзабилити-тест: если возможно, 3-5 пользователей с нарушением зрения; зафиксировать замечания в `docs/a11y-report.md`.
- **Готово, когда:** нет критических нарушений WCAG AA, отчёт заполнен.

### Этап 7. Деплой и документация
- Деплой фронта (Vercel/Netlify) и бэка (Yandex Cloud/Render).
- README: запуск, переменные окружения, горячие клавиши, архитектура.
- Документация для защиты: HCI-обоснование решений, результаты тестов, ограничения.

## 5. Схема БД (Supabase)

- `profiles` (id, role: child|teacher, language, settings jsonb)
- `materials` (id, owner_id, prompt, image_url, alt_text, long_description, language, created_at)
- `lessons` (id, order, title_kk, title_ru, content jsonb)
- `lesson_progress` (user_id, lesson_id, status, updated_at)

Включить Row Level Security: пользователь видит только свои записи, учитель только записи привязанных детей.

## 6. Безопасность и этика

- Не собирать лишние персональные данные детей (достаточно псевдонима).
- Согласие родителя или учителя при регистрации.
- Ключи API только на бэкенде, на фронт не передавать.
- Модерация генерации, лимиты запросов на пользователя.

## 7. Основной пользовательский сценарий (для приёмки)

1. Ребёнок открывает сайт, голос приветствует и объясняет управление.
2. Говорит: «Создать картинку: кот на крыше».
3. Система озвучивает «Картинка создаётся», затем «Готово».
4. Автоматически звучит описание: кратко, затем подробно по запросу.
5. Ребёнок говорит «сохранить» и находит работу в галерее.

## 8. Риски

| Риск | Решение |
|---|---|
| Бесплатные лимиты ИИ-API исчерпаны или изменились | Адаптеры и фолбэк на браузерные API, кэширование |
| Плохая поддержка казахского в TTS/STT | Проверить провайдеров на раннем этапе (Этап 2), держать русский как запасной |
| Web Speech API не работает в некоторых браузерах | Клавиатурный/текстовый режим как равноправная альтернатива |
| Неточные описания изображений | Возможность редактировать описание учителем, пометка «сгенерировано ИИ» |
