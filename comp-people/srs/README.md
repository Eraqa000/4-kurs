# AudioCanvas

Доступный веб-интерфейс для детей с нарушением зрения: создание картинок с помощью ИИ и обучение
аудиоописанию. План проекта — в [PLAN.md](PLAN.md).

**Статус:** Этапы 0–5 выполнены, все данные в локальной БД SQLite (деплой не делается), Этап 6 выполнен частично (автоматика готова, ручные проверки ждут), с отступлениями от плана: вместо Supabase используется локальная БД SQLite, нет входа и режима учителя (см. ниже).

**Голосовые команды:** создать, слушать, повторить, назад, сохранить, дальше (kk/ru). Команды можно ввести и текстом — это равноправная альтернатива голосу.

## Запуск

Фронтенд (http://localhost:5173):

```bash
cd frontend
npm install
npm run dev
```

Бэкенд (http://localhost:8000, документация на `/docs`):

```bash
cd backend
cp ../.env.example .env
uv sync
uv run uvicorn app.main:app --reload
```

## Проверки

CI: `.github/workflows/ci.yml`. Lighthouse accessibility ≥ 95: `cd frontend && npm run build && npm run preview` и в другом окне `npm run lighthouse`. Подробности и ручные проверки — в `docs/`.

```bash
cd frontend && npm run lint && npm run typecheck && npm test
cd backend && uv run ruff check . && uv run pytest
```

## Горячие клавиши

Отключаются в «Настройках» (WCAG 2.1.4).

| Клавиша | Действие |
|---|---|
| `?` | Список горячих клавиш |
| `Alt+1` | Создать |
| `Alt+2` | Мои работы |
| `Alt+3` | Уроки |
| `Alt+4` | Настройки |
| `R` | Повторить последнюю озвученную фразу |
| `V` | Включить/выключить микрофон |
| `1`–`9` | В уроке: выбрать вариант ответа |
| `Esc` | Пауза речи, второе нажатие — остановка; закрывает окно |

## Структура

- `frontend/` — React + TypeScript + Vite; `src/a11y` — фокус, live-регионы, хоткеи, модалки.
- `backend/` — FastAPI; `app/providers` — адаптеры ИИ-сервисов (Этап 3).
- `backend/data/` — локальная база SQLite (в `.gitignore`).
- `supabase/schema.sql` — исходная схема под Supabase; сейчас не используется.
- `docs/` — документация и отчёт по доступности.

Ключи API хранятся только в `backend/.env`.

## API (Этап 3)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/generate` | `{prompt, language}` → `{image_id, image_url, cached}` |
| GET | `/api/images/{id}` | сама картинка |
| POST | `/api/describe` | `{image_id, language}` → `{alt_text, long_description, ai_generated}` |

Модерация запросов и ответов, кэш и лимиты (`RATE_GENERATE_PER_MIN`, `RATE_DESCRIBE_PER_MIN`,
`CACHE_TTL_SECONDS`) настраиваются в `.env`. Пока работают провайдеры-заглушки (`stub`):
они рисуют три фигуры и честно описывают их. Реальные сервисы подключаются классами
`ImageProvider` / `DescriptionProvider` в `backend/app/providers/` и регистрацией в `registry.py`.

## Провайдеры ИИ: Google Gemini

В `backend/.env` задай `IMAGE_PROVIDER=gemini`, `DESCRIPTION_PROVIDER=gemini` и ключи
(можно один и тот же ключ в `IMAGE_API_KEY` и `VISION_API_KEY`). По прайсу Google на момент
выбора: описание (`gemini-3.1-flash-lite`) бесплатно в пределах free-tier, **генерация картинок
бесплатного уровня не имеет** (нужен платный проект). Это проверяется на странице цен Google —
условия меняются. При неверной конфигурации сервер не запустится.

## Бесплатная связка: Cloudflare + Gemini

`IMAGE_PROVIDER=cloudflare` (FLUX.1 schnell через Workers AI) и `DESCRIPTION_PROVIDER=gemini`.
Cloudflare: 10 000 нейронов в день бесплатно, одна картинка 1024×1024 стоит около 173 нейронов,
то есть **примерно 57 картинок в день**. Повторный запрос берётся из кэша и лимит не тратит.

## Галерея и экспорт (Этап 5)

Работы хранятся в SQLite (`backend/data/audiocanvas.db`): картинка, запрос и описания сразу на
kk и ru. Описание, которое правил человек, помечается «отредактировано» вместо «создано ИИ».

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/materials` | сохранить `{image_id}` (повтор не создаёт дубль) |
| GET | `/api/materials` | список моих работ |
| GET/PATCH/DELETE | `/api/materials/{id}` | прочитать, исправить текст, удалить |
| GET | `/api/materials/{id}/image` | картинка |
| GET | `/api/materials/{id}/audio?language=` | аудио описания (MP3, если на сервере есть ffmpeg, иначе WAV) |
| GET | `/api/materials/{id}/export?language=` | ZIP: картинка + `description.txt` + аудио |

**Важное ограничение: входа нет.** Работы разделяются заголовком `X-Owner-Id` со случайным
идентификатором устройства (хранится в localStorage). Это разделение списков, а не защита:
для нескольких пользователей и режима учителя нужна аутентификация. Скачивание картинки,
аудио и ZIP идёт по случайному UUID работы без заголовка, чтобы работали `<img>` и ссылки.

Аудио для экспорта делает Gemini TTS (`TTS_PROVIDER=gemini`, поддерживает казахский и русский),
результат кэшируется. Для MP3 на сервере нужен `ffmpeg`.

## Локальная база данных

Файл `backend/data/audiocanvas.db` (SQLite) создаётся при первом запуске бэкенда. Таблицы:

| Таблица | Что хранит |
|---|---|
| `materials` | сохранённые работы: запрос, картинка, владелец (идентификатор устройства) |
| `material_texts` | описания работы на kk и ru, флаг «правил человек» |
| `lesson_progress` | статус каждого урока (`not_started`, `in_progress`, `done`) для владельца |

Статус `done` на сервере не понижается. Браузер хранит копию прогресса в localStorage и при
запуске сливает её с сервером. Тексты уроков живут во фронтенде (`frontend/src/features/lessons`),
в БД их нет. Таблиц `profiles` и `lessons` из исходного плана нет: нет входа и режима учителя.

```bash
cd backend
sqlite3 data/audiocanvas.db ".tables"                              # посмотреть таблицы
sqlite3 data/audiocanvas.db "select id, prompt from materials;"    # посмотреть работы
cp data/audiocanvas.db data/backup.db                               # резервная копия
rm data/audiocanvas.db                                              # сбросить всё (создастся заново)
```

Путь к файлу задаётся переменной `DATABASE_PATH`. Картинки лежат в БД как BLOB (около 0,2–0,7 МБ
каждая), поэтому при большом числе работ файл вырастет.

## Вступление-помощник (аудио при открытии сайта)

При каждом открытии и обновлении сайта показывается окно «Привет! Голосовой помощник», и **через
3 секунды само начинает звучать заранее записанное аудио** (kk или ru, по языку интерфейса,
текст виден в окне). В записи в первые секунды сказано, как остановить её.

| Клавиша | Действие |
|---|---|
| `Enter` или `Space` | остановить подсказку и начать работу; в первые 3 секунды — пропустить совсем |
| `Esc` | то же самое |
| `H` или кнопка «Дауыстық көмекші» внизу | послушать подсказку снова |

Подсказка отключается в «Настройках» («Показывать подсказку при открытии сайта»). Если выключена
«Озвучивать интерфейс», звук сам не играет (окно остаётся, запустить можно кнопкой).

**Ограничение браузеров.** Chrome, Firefox и Safari могут запретить звук без действия
пользователя. Тогда окно говорит об этом, а запись начинается с первого нажатия клавиши (на
главной кнопке достаточно `Enter`). Чтобы звук включался сам, разрешите сайту звук:
Chrome → Настройки → Конфиденциальность и безопасность → Настройки сайтов → Звук → «Разрешить
воспроизведение звука» → добавить адрес сайта (например `http://localhost:5173`). Chrome также
сам разрешает автозвук сайтам, которыми часто пользуются.

Аудио лежит в `frontend/public/audio/` и готовится заранее. Тексты — в
`frontend/src/features/intro/intro-texts.json`; после правки текста пересоздайте записи:
`cd backend && uv run python scripts/generate_intro_audio.py` (нужен `VISION_API_KEY`).

## Дизайн

Основа — проект Stitch «AudioCanvas Accessible Learning App», дизайн-система «Luminous Haptic
Canvas»: тёмный холст `#0B1220`, янтарь `#FFD23F`, голубой `#38BDF8`, рамки 3px, радиус 16px,
кнопки не ниже 64px, контур фокуса 4px с отступом 4px, быстрые настройки в шапке (A−/A+, контраст,
язык), панель подсказок клавиш внизу. Вариант «высокий контраст» — светлая тема из макета.

Отличия от макета ради доступности:
- рамки элементов управления светлее (`#64748b`, а не `#334155`), иначе контраст 1,9:1 меньше 3:1
  (WCAG 1.4.11); `#334155` оставлен только для декоративных рамок карточек;
- шрифт Atkinson Hyperlegible Next не содержит кириллицы, поэтому латиница набирается им, а
  казахские и русские буквы — шрифтом Noto Sans (оба подключены локально);
- из макета не перенесены элементы без функций в приложении: «Мұғалім панелі», «Күн кеңесі»,
  примеры-галерея, индикатор «Дыбыс: 100% дайын».
